## Commit Convention

### 커밋 메시지 형식

```text
<작업 타입>: <작업 내용>
```

### 커밋 컨벤션

| **타입** | **설명** |
| --- | --- |
| `begin` | 프로젝트 시작 |
| `feat` | 새로운 기능 추가 및 구현 |
| `docs` | 문서 파일 추가 및 수정 |
| `add` | 기존 기능에 코드 추가 및 수정 |
| `typos` | 단순 오타 수정 |
| `fix` | 버그 및 에러 수정 |
| `test` | 테스트 코드 작성 및 수정 |
| `rename` | 파일·경로 이동 또는 이름 변경 |
| `refactor` | 코드 리팩토링 |
| `comment` | 주석 추가 및 변경 |
| `remove` | 파일·코드 삭제 |
| `branch` | 브랜치 추가 및 병합 |
| `chore` | 빌드·패키지 관리·환경 설정 변경 |

---

## Branch Convention

### 브랜치 구조

| **브랜치** | **역할** |
| --- | --- |
| `main` | 배포 가능한 안정 버전 관리 |
| `develop` | 개발 중인 기능을 통합하는 브랜치 |
| `feature/기능명` | 개별 기능을 개발하는 브랜치 |

---

## Pull Request Convention

### PR 생성 규칙

1. 기능 개발 완료 후 `develop`을 대상으로 PR을 생성합니다.
2. PR 제목은 커밋 메시지와 동일한 형식을 사용합니다.
3. PR 본문에는 작업 내용, 주요 변경 사항 및 테스트 결과를 작성합니다.
4. **최소 1명 이상의 리뷰 승인**을 받습니다.
5. 필요한 테스트 및 코드 리뷰를 완료한 후 병합합니다.
6. 병합이 완료된 기능 브랜치는 삭제합니다.

### PR 제목 형식

```text
<작업 타입>: <작업 내용>
```

**작성 예시**

```text
feat: 회원가입 API 구현
fix: 로그인 토큰 만료 오류 수정
refactor: 사용자 서비스 구조 개선
docs: API 명세서 업데이트
```
