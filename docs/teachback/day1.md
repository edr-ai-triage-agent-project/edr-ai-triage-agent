## 🔍 기록 담당이 설명한 것

- EDR 시뮬레이션 데이터 분석, OpenSearch 인덱스 설계 및 조사 도구 구현을 진행했다.

**1. EDR 데이터 관찰**
- 가상 EDR 이벤트 3,161건과 정답 라벨 14건을 생성했다.
- `credential_dump` 시나리오(`sc-003`, `WS-006`)의 이벤트 3건을 분석했다.
- PID·PPID를 통해 `cmd.exe` → `rundll32.exe` 관계와 `d.dmp` 파일 생성 기록을 확인했다.
- 부모 `explorer.exe`의 실행 이벤트는 확인되지 않아 실제 근거와 추정을 구분했다.

**2. OpenSearch 인덱스 설계 (REC-1)**
- 정확 일치 검색은 `keyword`, 내부 단어 검색은 `text`를 사용하도록 매핑했다.
- 명령줄에는 `text`와 `keyword`를 함께 적용하고 `dynamic: strict`를 설정했다.
- 이벤트 3,161건을 OpenSearch에 적재하고 검색을 검증했다.
- `MiniDump` 단어 검색 4건, 전체 명령줄 정확 일치 검색 4건을 확인했다.

**3. 조사 도구 구현 (REC-2~4)**
- `get_process_tree()`: 부모·자식 프로세스 조회
- `get_process_activity()`: 프로세스별 파일·네트워크 등 활동 조회
- `get_host_timeline()`: 특정 시간 전후의 이벤트 조회
- 모든 조회에 `host` 조건을 포함하고 `event_id`를 유지하도록 구현했다.

**4. 검증 결과**
- 조사 도구 테스트: **8 passed**
- 실제 OpenSearch 연동 조회 성공
- `WS-006`의 `rundll32.exe` 조사 결과:
  - 부모 `cmd.exe` 1건
  - 덤프 파일 생성 이벤트 1건
  - 호스트 타임라인 19건 (`truncated=False`)

**5. 설계 결정 및 한계**
- 서로 다른 PC의 동일 PID가 섞이지 않도록 `host` 조건을 사용했다.
- 부모 이벤트가 누락되면 확인 가능한 계보까지만 반환하도록 했다.
- 명령줄을 요약하여 LLM에 전달하는 데이터 양을 줄이고, `event_id`는 근거 검증을 위해 유지했다.
- 조회 결과가 제한을 초과하는 상황은 추가 검증이 필요하다.

**핵심 설명**

조사 도구는 악성 여부를 직접 판정하는 것이 아니라, 프로세스 실행 관계와 활동 기록을 조사하여 AI 판정에 필요한 근거를 제공한다.
